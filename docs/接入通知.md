# 接入通知（总管整段复制发群；成员按步骤粘贴给自己的 Claude Code）

> 本文件是发群用的可直接发送版本；规则以 `CLAUDE.md` 为准，接入细节以 `docs/协作者交接文本.md` 为准。

---

各位好，机械臂（Seeed reBot DevArm B601-RS）项目仓库已经建好：https://github.com/relativequntum/robot-arm

协作方式一句话：所有讨论和任务都走 GitHub issue，每人本地用 Claude Code 干活。规则写在仓库根目录 CLAUDE.md 里，你的 Claude 打开仓库目录时会自动加载并照做；每次 git pull 后看 docs/看板.md 就能看到自己名下的待办，不用盯群。

接入四步（约 15 分钟，除「登录授权」要你本人点浏览器外，其余都是让你的 Claude 做）：

**0. 准备**：装好 git、Python 3.10+、Claude Code。把你的 GitHub 登录名发我，我邀请你进仓库，收到邮件后点 Accept（不接受就 push 不了、也没法给你指派任务）。

**1. 建目录**：新建一个空文件夹 `robot-arm`，在终端里 `cd` 进去运行 `claude` 打开 Claude Code。

**2. 装 gh 并登录**：把下面这段整段粘贴给 Claude。登录那一步按它的提示由你本人操作（系统终端执行，或在 Claude Code 输入框里输入带 `!` 前缀的命令）：

```text
请帮我安装 GitHub CLI 并确认可用。

1. 先执行 gh --version 检查是否已安装；已装就跳到第 3 步。
2. 未安装则按我的系统安装：Windows 执行 winget install --id GitHub.cli -e；macOS 执行 brew install gh；Ubuntu 按 https://github.com/cli/cli/blob/trunk/docs/install_linux.md 的官方 apt 源步骤装。装完提醒我新开一个终端（PATH 才会生效）。
3. 登录这一步必须我本人操作，你不要替我跑。告诉我两种做法任选：在系统终端（PowerShell / Windows Terminal，macOS、Linux 用系统终端）执行
   gh auth login --web --hostname github.com --git-protocol https
   或者直接在这个 Claude Code 输入框里输入带 ! 前缀的同一条命令（! gh auth login --web --hostname github.com --git-protocol https）。它会问是否用 GitHub 凭据配置 git（选 Yes），然后打印一次性 code 并等我按 Enter 打开浏览器，把 code 贴进去完成授权。
4. 我说完成后，你执行 gh auth status 给我看结果，并用 gh api repos/relativequntum/robot-arm --jq .permissions.push 验证我对本项目仓库有 push 权限；如果是 false，说明我还没接受仓库邀请，提醒我去邮箱或 GitHub 通知里接受（或找总管发邀请），不要去试别的地址。
```

**3. 启动接手**：授权成功后，把下面这段整段粘贴给 Claude（**把第一行的姓名和登录名换成你自己的**）。它 clone 完会让你 `/exit` 再重新运行 `claude`，重启后把这段**再发一次**即可：

```text
我是本项目成员 ＜姓名＞，GitHub 登录名 ＜登录名＞，负责模块待总管分工。你是我的开发助手。
（本段如与仓库根目录的 CLAUDE.md 冲突，一律以 CLAUDE.md 为准。）

第一步：当前目录是空文件夹，请执行
git clone https://github.com/relativequntum/robot-arm.git .
clone 成功后提醒我：输入 /exit 退出，在同一个终端里重新输入 claude 启动（这样仓库根目录的 CLAUDE.md 才会被自动加载，否则它只是一篇被手动读过的普通文档），重启后我把这段文本再发一次，你从第二步开始。

第二步：依次阅读并严格遵守：
1. CLAUDE.md（开发规范与协作红线，最高优先级）
2. README.md（项目目标、硬件简介、协作方式、本地环境要求）
3. docs/硬件/官方文档索引.md（B601-RS 官方参数、软件栈 MotorBridge / reBotArm_control_py / LeRobot / 仿真、CAN 初始化命令、链接清单、注意事项，以及官方文档未覆盖的存疑项——这些不要臆测，需要就开 issue 或去实机核实）
4. docs/看板.md（我名下的待办）与 docs/开放问题结论台账.md（已定下的口径）

我的文件归属：目前未分工，不要新建 src/ 下的目录，也不要改他人文件——模块划分与 src/ 目录结构由 issue #2 [裁决] 确定后回填到 CLAUDE.md 的归属表。唯一例外：docs/开放问题结论台账.md 与 docs/硬件/官方文档索引.md 第七节是全员可写的结论回填位，我作为会签提出方（或硬件问题的求证方）关闭 issue 后要按规定回填一句话结论；回填以外的改动仍归总管。

当前阶段任务：
1. 用 gh issue view 1 --comments 读 issue #1 的任务书，带我逐条完成（配置 git config --global pull.rebase true、登记信息），登记内容由我确认后你用 gh issue comment 1 贴出。
2. 然后 git pull，读 docs/看板.md 里我登录名下那一节，按状态标注逐条处理——被指派的、被 @ 的、我自己提出的都在里面。如果看板里找不到我的登录名章节，说明总管还没把我登记进 workflow 的 MEMBERS，不要据此判定为「无待办」：改用 gh issue list --assignee @me --state open 查，并浏览看板的模块章节找 @ 到我的条目，同时提醒我去找总管补登记。
3. 需要看细节时用 gh issue view N --comments 读全文和评论，向我复述任务与验收标准，然后按 issue 要求执行并逐条回帖。
4. 确认我的登录名章节存在、且其中没有条目时，停下来等总管指派，不要自行开工改代码；我想做点什么就先开 [任务] / [会签] issue。
5. 对 issue #2 [裁决]（模块划分）如有想法，起草附议意见，我确认后你贴到 #2 评论区。

工作纪律：开始前 git pull；小步 commit（中文提交信息）；每次结束必 git push；禁止 force push、禁止改他人文件（结论台账与硬件索引第七节的回填除外）、禁止提交数据文件与密钥（大文件与数据放 local-data/，不进 git；小体量共享样例放 share-data/）；commit 信息里不要随手写 closes #N；跨模块问题开 issue，不要写在文档里就当发出了；表态类 issue 评论必须我过目定稿再贴，完成通报类可以直贴，代贴时正文必须是可直接上墙的定稿、不许带草稿抬头；实机相关的事在 Linux 机器上做，Windows 只写代码与文档；git 报错原样发给我，不要强行解决。
```

**4. 之后怎么用**：每次开工对 Claude 说「git pull，看 docs/看板.md 我名下待办，逐条处理」；被指派或被 @ 时说「我在 issue #N 被指派了会签。先 git pull 看看板我名下待办，再用 gh 读 #N 全文和评论，结合相关文档给出意见草稿，我确认后你用 gh issue comment 贴出」。

卡住的地方直接在 issue #1 下回帖，不用群里刷屏；只有阻塞开工、有截止时间、需当日回应三种情况才在群里 @ 我。
